# GO-CONVENTIONS — EMS coding conventions (naming, errors, context, authz, logging)

> **Scope.** The concrete idioms the real `employee-management-service` (EMS) repo follows, so any
> new Go code (e.g. a Fabric anchor-service) reads like the existing codebase. Grounded in
> `/Users/chan/www/employee-management-service`. For the layering these conventions sit inside, read
> `GO-ARCHITECTURE.md`; for the language-agnostic version of these rules,
> `> See coding-standards-backend/references/naming.md`,
> `> See coding-standards-backend/references/error-handling.md`,
> `> See coding-standards-backend/references/auth-and-authz.md`.

## 1. Packages, files, and naming

- **Package = feature directory**, snake_case: `internal/employee_transfer`, `internal/company_setting`.
  The Go package name matches the leaf dir `[code: ems/internal/employee_transfer/]`.
- **Interface files** are prefixed `i`: `irepository.go` declares `Repository`, `iservice.go`
  declares `Service` `[code: ems/internal/education/repository/irepository.go]`,
  `[code: ems/internal/user/service/iservice.go]`.
- **Constructors** are `NewX`: `NewRepository`, `NewService`, `NewGuard`, `NewBaseHTTPHandler`,
  `NewContext`, `NewPool` `[code: ems/internal/education/repository/repository.go]`,
  `[code: ems/internal/base/authz/guard.go]`.
- **Interface names are bare** (`Repository`, `Service`, `AuthorizationGuard`); the implementing
  struct is the unexported `repo` / `service` / `Guard`
  `[code: ems/internal/education/repository/repository.go]`, `[code: ems/internal/base/authz/guard.go]`.
- **Generated files** end `.gen.go` and carry `// Code generated by gorm.io/gen. DO NOT EDIT.`; the
  table name is a const `TableNameTblUser = "tbl_user"` `[code: ems/internal/datasource/model/tbl_user.gen.go]`.
- **Import aliases** are used heavily to disambiguate the many same-named sub-packages —
  `empRepo`, `usrSer`, `accRoleService`, `fEduRepo` — as seen across `cmd/boot.go`'s import block
  `[code: ems/cmd/boot.go]`.
- **goimports local-prefix** is the module path: imports are grouped stdlib → third-party →
  `bitbucket.org/mid-kelola-indonesia/employee-management-service/...`
  `[code: ems/.golangci.yml]`.
- Exported constants group by domain, e.g. role codes `RoleSuperAdmin = 1 … RoleFinance = 5`
  `[code: ems/internal/user/domain/user/user.go]`.

## 2. Error handling — `pkg/errs`

EMS does **not** return bare `error` from handlers/services/repos. It uses a custom `errs.Error`
interface implemented by `errCustom`, which carries a message, the wrapped `Err`, an `ErrorType`,
and a captured `File` + `Stack` `[code: ems/pkg/errs/error.go]`.

- **`ErrorType` doubles as the HTTP status** for the common cases: `ErrorTypeBadRequest = 400`,
  `ErrorTypeUnauthorized = 401`, `ErrorTypeForbidden = 403`, `ErrorTypeNotFound = 404`,
  `ErrorTypeConflict = 409`, `ErrorTypeUnprocessableEntity = 422`, `ErrorTypeInternalError = 500`
  `[code: ems/pkg/errs/factory.go]`.
- **Factory functions** name the intent: `errs.New`, `errs.Wrap`, `errs.WrapWithErrorType`,
  `errs.WrapWithMessage`, `errs.NewNotFoundError`, `errs.NewBadRequest`, `errs.NewConflictError`,
  `errs.NewUnprocessableEntityError`, `errs.NewUnautorizedError` (sic)
  `[code: ems/pkg/errs/factory.go]`.
- **Wrap at the boundary you cross.** Repositories wrap raw GORM errors:
  `return nil, errs.Wrap(result.Error)` `[code: ems/internal/education/repository/repository.go]`.
  A not-found read returns `(nil, nil)` when that is a valid business state (see
  `GetLastInformalEducationByUserID`) `[code: ems/internal/education/repository/repository.go]`.
- **Type checks** flow through the interface: `err.IsErrNoRows()`, `err.IsType(errs.ErrorTypeNotFound)`,
  and `errs.IsDuplicateKey(err)` which detects both `gorm.ErrDuplicatedKey` and MySQL error 1062
  `[code: ems/pkg/errs/error.go]`, `[code: ems/pkg/errs/factory.go]`.
- `errCustom` implements `Unwrap()` so `errors.Is/As` still work
  `[code: ems/pkg/errs/error.go]`.

**Recommendation** for new Fabric-adjacent code: keep returning `errs.Error`; map Fabric SDK/gateway
failures to `errs.WrapWithErrorType(..., errs.ErrorTypeInternalError)` and reserve 4xx types for
caller-input problems — matching how `Guard` errors are mapped in `guardError`
`[code: ems/app/api/router.go]`.

## 3. Context propagation

- **`*app.Context` is the request-scoped carrier.** It embeds `*gin.Context`, is created once per
  request by `NewContext`, and is passed down handler → service → repository
  `[code: ems/internal/base/app/context.go]`.
- **The underlying `context.Context` carries company + archive flags.** `NewContext` calls
  `db.SetCompanyContext(ctx, companyID)` so the encryption plugin and other downstream layers can
  read the tenant without an explicit parameter `[code: ems/internal/base/app/context.go]`,
  `[code: ems/pkg/db/company_context.go]`. Retrieval falls through struct-key, gin-string-key, and
  the wrapped request context (`GetCompanyContext`) `[code: ems/pkg/db/company_context.go]`.
- **Always thread the context to GORM**: `r.db.WithContext(ctx)` on every query
  `[code: ems/internal/education/repository/repository.go]`.
- Repository/service methods take either `*app.Context` (when they need identity/company) or plain
  `context.Context` (for writes that only need cancellation), e.g.
  `StoreInformalEducation(ctx context.Context, …)` `[code: ems/internal/education/repository/irepository.go]`.
- `> See coding-standards-backend/references/distributed-tracing.md` for the tracing rationale; EMS
  starts DataDog spans in `RunAction` and tags `scope`, `company_id`, `sso_id`
  `[code: ems/internal/base/handler/base.go]`.

## 4. Authentication — gateway-header trust (`base/handler/base.go`)

EMS never authenticates end users itself; it trusts **Kong-injected headers** and validates a shared
API key `[code: ems/internal/base/handler/base.go]`:

- `X-Api-Key` must equal `EMSAPIKey` (or the secondary key) or the request is rejected 401.
- `X-SSO-User-ID` (fallback `X-Authenticated-Userid`) identifies the user; `X-Company-ID` the tenant;
  `X-Scope` selects the scope: `company`, `internal`, or `user` (`constant.AUTH_SCOPE_*`).
- Any path containing `api/v1/internal` is forced to INTERNAL scope.
- **Consultant multi-company:** when `X-Company-ID` differs from the user's home company, EMS looks
  up a consultant identity (`GetUserConsultantIdentity`); if none exists the identity is stripped
  (role/company zeroed) rather than trusted `[code: ems/internal/base/handler/base.go]`.
- **Auth hardening** (`AuthHardeningShadow` / `AuthHardeningEnforce`): `X-Ignore-Access-Role-Validation`
  is honoured only in INTERNAL scope; on user/company scope it is logged (shadow) or forced off
  (enforce) to close a privilege-escalation vector `[code: ems/internal/base/handler/base.go]`,
  `[code: ems/app/appconf/config.go]`. This is the code the knowledge-graph NIST-Zero-Trust frame
  (E6) and gap **G-18** (gateway trust boundary) map onto.

## 5. Authorization — the base RBAC + Guard patterns

Two distinct layers, both sourcing identity from the trusted context only:

- **Role RBAC — `authz/employee_rbac.go`.** `CanAccessEmployeesData` / `CanEditEmployeesData` are the
  single source of truth for "may this end-user view / edit employee data?". Denied for a nil actor,
  the **Employee** role, the **Finance** role, and any actor lacking `EmployeeView`; EDIT
  additionally requires `EmployeeEdit == 1`. The INTERNAL-scope bypass short-circuits to allow.
  Scope conditioning (apply only in USER scope) is the caller's responsibility, documented on the
  functions `[code: ems/internal/base/authz/employee_rbac.go]`.
- **Object-level Guard — `authz/guard.go`.** `AuthorizationGuard.ValidateResourceOwnership` compares
  a resource's true owning company (via an injected `ResolverFunc`) to `GetAuthenticatedCompanyID()`
  and **masks any mismatch or not-found as 404** — no cross-tenant existence leak. Unregistered
  resource types **fail closed** (500), never open `[code: ems/internal/base/authz/guard.go]`,
  `[code: ems/internal/base/authz/registry.go]`. This is the BOLA/IDOR defense (OWASP API1, frame E5)
  and is fully detailed in `GO-SECURITY.md`.

Identity comes **only** from context (`GetScope`, `GetAuthenticatedCompanyID`), never from client
path/body/header params — stated explicitly in the guard's doc comment
`[code: ems/internal/base/authz/guard.go]`. `> See coding-standards-backend/references/auth-and-authz.md`.

## 6. Configuration — `app/appconf`

- One typed `Config` struct; `InitAppConfig()` reads `os.Getenv` into it; a separate
  `InitAppConfigForTest()` sets `AppEnv = "test"` and skips Redis/PII init as needed
  `[code: ems/app/appconf/config.go]`.
- **Environment helpers:** `IsStaging()` == `AppEnv=="development"`, `IsProd()` == `"production"`,
  `IsDebug()` == `AppDebug=="True"` `[code: ems/app/appconf/config.go]`.
- **Feature toggles** are booleans parsed from string env: `== "True"` (most) or `== "true"`
  (e.g. `FeaturePublicAPIExpose`, `AuthHardeningEnforce`, `AuthHardeningShadow`, … — not exhaustive) —
  note the casing difference is real and load-bearing `[code: ems/app/appconf/config.go]`.
- Numeric/duration config validates and falls back with a `slog.Warn`, e.g. worker-pool sizes and
  DB pool timings `[code: ems/app/appconf/config.go]`.
- **Never invent env keys.** The PII-encryption keys (`PII_ENCRYPTION_KEY`, `_IV`, `_V2`,
  `_ACTIVE_VERSION`, `_TOGGLE_ENABLED`, `_READ_ENABLED`, `_WRITE_ONLY`) are parsed and format-
  validated in `initPIIEncryptionConfig` (`validateEncryptionKeyIV`: key 64 hex, IV 32 hex)
  `[code: ems/app/appconf/config.go]`. See `GO-SECURITY.md`.

## 7. Logging & audit (ULMS)

- **Structured logging is `log/slog`**, initialized by `pkg/logger.InitMekariLogger()`
  `[code: ems/cmd/boot.go]`, `[code: ems/pkg/logger/mekari_logger.go]`. Repos/services log with
  `slog.InfoContext(ctx, …)` / `slog.Error(...)`.
- **One request log line per request** via `api.RequestLogger`: emits `request_id`, `method`, `path`,
  `client_ip`, `x_company_id`, `x_scope`, `status`, `latency_ms`; escalates level to Warn on 4xx and
  Error on 5xx; skips health-check paths `[code: ems/app/api/middleware_logger.go]`.
- **Sensitive-field masking:** `LOG_MASK_FIELDS` (comma-separated) builds a set; `maskValue`
  recursively replaces those JSON fields with `*****` in logged bodies
  `[code: ems/app/api/middleware_logger.go]`, `[code: ems/app/appconf/config.go]`.
- **ULMS = the audit sink.** On a non-GET 2xx response, `GetULMSLogMessage` builds a `LogMessage`
  and `ULMSService.SendLog` publishes it to a per-day Kafka topic `ulms.YYYYMMDD` (Asia/Jakarta),
  falling back to a DB `SaveLog` when the broker is unavailable
  `[code: ems/internal/base/handler/base.go]`, `[code: ems/internal/base/service/ulms/ulms.go]`.
  This existing audit trail is the natural companion to a Fabric tamper-evident audit anchor (D12);
  `> See coding-standards-backend/references/logging-observability.md`.

## 8. Fact vs. recommendation

Everything cited above is documented fact read from the repo. Where this project layers Fabric on top
are **assumptions** tracked in `11-execution/grounding-gaps.md`, not conventions of this repo — e.g.
**[ASSUMPTION] (gap G-11):** HRIS roles map to X.509 OUs; and **[ASSUMPTION] (gap G-15):** Fabric MSP
keys stay separate from the app AES PII keys.
